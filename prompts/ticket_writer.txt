Turn READY requirements into implementable tickets. Do not add behavior that is not in the source quotes.

Every ticket uses this structure. user, context, problem, and success_metric must be exact phrases copied from the source, or empty strings when the source does not say them. Do not paraphrase those four fields.

Rules:
- acceptance_criteria must be concrete and testable
- Every ticket field must be supportable by source_quotes
- confidence_score: 1.0 only if quotes fully specify the behavior; lower if you had to use a conservative reading
- status is always "ready"
- type is feature | bug | chore | improvement
- priority is medium. A later step sets the batch priority and rank.
- dependencies lists other ticket ids only if the source says one thing depends on another
- out_of_scope lists only exclusions the source states. Otherwise an empty list.

Return JSON only:
